# Bullet points

This is where most resumes fail. A bullet exists to show (1) the technical work you did, (2) the challenge
you overcame, (3) the impact it had.

## Formulas

**STAR** — Situation, Task, Action, Result. Situation is usually covered by the role header (company, title,
dates), so the bullet is Task + Action + Result.

**XYZ** — "Accomplished [X] as measured by [Y] by doing [Z]." Google's formulation.

**CAR** — Challenge, Action, Result.

They collapse to the same thing: *what you did → how you did it → what changed because of it.*
If you can quantify the result, move the number toward the front of the bullet.

## Mechanics

- Start with a strong **past-tense action verb**. Present tense only for a current role if you're consistent.
- 1–2 lines. One sentence preferred, two maximum. Never a paragraph.
- 3–5 bullets per role; more only for a long tenure.
- Most relevant/impressive bullet first — some readers only read the first one.
- No personal pronouns (I, we, my, our, their).
- No trailing periods.
- Bullets must not extend further right than the dates column.
- Never leave a 1–4 word orphan on a wrapped line, and never let a word hyphenate across lines.
- Avoid sub-bullets. Avoid apostrophes, `&`, and `/`.
- Cut adjectives and adverbs — "successfully", "efficiently", "seamlessly", "robust", "cutting-edge".
- Digits, not words: "8", not "eight".
- Skip fluff everyone does: attended standups, used Git, wrote unit tests, did code reviews, collaborated
  with the team.
- Don't bold keywords inside bullets — it's distracting and defeats emphasis.

## Verbs

**Good:** analyzed, architected, automated, built, created, decreased, designed, developed, implemented,
improved, increased, integrated, led, migrated, optimized, published, reduced, refactored, shipped, wrote.
("Led" is the past tense of "lead".)

**Weak — they say you were present, not that you did anything:** aided, assisted, coded, collaborated,
communicated, executed, exposed to, gained experience, helped, participated, programmed, ran, used,
worked on, responsible for.

**Inflated / awkward — avoid:** amplified, conceptualized, crafted, elevated, employed, engaged,
engineered, enhanced, ensured, fostered, headed, honed, innovated, mastered, orchestrated, perfected,
pioneered, revolutionized, spearheaded, transformed.

**Frequently misused:** leverage, enhance, **utilize** (never use it — it's always a longer word for "use").

## Bad → why → better

> Developed backend web and mobile applications using Ionic with a Node.js backend

Vague. Which service? API, data layer, caching? What changed as a result?

> Developed SpringBoot microservices capable of bringing a user quote to insurance policy

Vague. Which service, what was hard about it, what did you actually solve?

> Developed and maintained user-friendly React Native based restaurant decision-making mobile application

Vague and self-congratulatory. What made it user-friendly? How was the decision engine implemented?

> Worked on an international team on various b2b projects built using Angular

Says nothing. Which projects, what work, what challenges?

> Drove $5M in revenue by completely automating the data retrieval process for 6+ GB of data per month

Better — has impact and scale — but no technical content. Automated how? Scripts, pipeline, off-the-shelf?

The same accomplishment, getting better each step:

1. Led the design and analysis of a DC fast charging station
2. Designed the company's flagship DC fast charging station on time and within budget
3. Designed the company's flagship DC fast charging station, reducing charge times by 23%
4. Designed the company's flagship DC fast charging station, generating $123M in sales annually

## Digging out content when you're stuck

**What did I do?** Did I solve a problem? Alone or on a team? How large was the team?

**How did I do it?** Why that approach? What tools, standards, or references? Did I test or validate, and
how did that change the design?

**What happened?** On time? Under budget? Did it work? How many users, requests, dollars, milliseconds?
What went wrong and what did I learn?

**Goal exercise:** recall the goals set at the project's start, how you met them, and — the useful part —
how you *exceeded* them. Write it all out long-form first, then compress to a bullet.

**Integration matters:** don't list parts. "Uses a Raspberry Pi and a stepper motor" is a parts list. How
your software drove those motors to hit a precision target is the engineering.

**Sensitive work:** describe the technology and the standard, not the program. "Developed C++ software for
evaluating aircraft subsystems on a [standard]-based test bench" instead of naming the classified platform.

  CNC mill and lathe, confirming reacted loads stayed below allowable limits

  time by 5s across all 5 events
- Implemented lean manufacturing to decrease labor and machine hours by 20% and reduce annual material costs

- Inspected a $3M bridge rehabilitation project by checking contractor work against contract plans and

- Facilitated sanitary and stormwater servicing for hundreds of properties by engaging municipal officers and
  subdivision planning, resulting in over 1,000 newly serviced properties
